Healthy-Pod Latency Degradation With Running/Ready Pods, Populated Endpoints, and Zero Restarts
Pod-scoped network delay: C: per-pod inbound/outbound latency isolated to target pod and correlated to fault window; R: peer pods on same node/namespace and downstream normal, no pod-level network fault evidence.
CPU/memory throttling or resource/node pressure: C: CFS throttling, high memory, GC pressure, or node pressure during fault window; R: these normal and no resource alerts.
Downstream/DB/dependency latency or saturation: C: deepest dependency has elevated own latency with derived caller timeouts/cancellations and slow backend/DB metrics; R: dependency spans, DB, and shared infrastructure normal.
Service-wide/node-wide network latency/loss: C: peers on same node/namespace or node-wide network show same latency/loss; R: only target pod affected and peer tests normal.
Application code delay/defect: C: extreme service-local request-handling latency, healthy pods, low error ratio, normal dependencies, and source/config inspection shows explicit sleep/delay; R: no explicit delay and other causes excluded.
Bad rollout/config: C: latency starts with rollout/config change and inspection shows bad config; R: stable config and no change correlation.
Load/traffic surge: C: traffic surge explains spike; R: no traffic surge.
Application exceptions: C: exception logs/traces correlate with latency; R: no exceptions and low error ratio.
Probe failures: C: failing probes/events during fault window; R: probes pass and pods remain Ready.
Endpoint churn: C: endpoint changes/removals during fault window; R: endpoints populated and stable.
Check order: pod/endpoints/probe/restart and exception/endpoint-churn status; resource metrics; traffic trend; dependency/DB/shared-infra spans; peer same-node/namespace network tests; per-pod latency isolation; source/config diff for sleep/delay or bad rollout.
