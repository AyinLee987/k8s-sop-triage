Differential diagnosis: elevated latency or RPS drop with healthy, ready pods
Pod-scoped network delay, including shared upstream/entry pod delay: confirm isolated per-pod RTT/inbound-outbound latency inflation for one pod, normal peer pods/node/downstream, correlation to fault window, and a pod-scoped delay metric or controlled latency test; rule out if RTT is normal or many pods are affected.
Node-level packet loss, service-wide/node-wide network issue, or broad congestion: confirm multiple unrelated co-located pods degrade together with simultaneous bidirectional packet-rate drop and NIC drop/error/retransmit metrics, and compare co-located workloads against unaffected nodes; rule out if isolated single-service slowness or no loss/drop/node-wide pattern.
CPU/memory/resource saturation, including CFS throttling, OOM, GC, and node CPU/memory/disk/network pressure: confirm throttling/OOM/GC or pressure metrics in the fault window; rule out if resource and pressure metrics are normal.
Downstream dependency, DB/cache latency, or independent backend faults: confirm the deepest service has elevated own latency via dependency spans/backend metrics while callers show only derived timeouts/cancellations; rule out if dependencies, DB, cache, and backends are normal.
Application code delay: confirm extreme service-local request-handling latency with healthy pods, low error ratio, normal dependencies, and source/config inspection showing an explicit sleep or delay in the request path; rule out if no code delay is found and another cause fits.
Application exceptions or error spikes: confirm a local exception/error surge; rule out by low error ratio and no exception surge.
Bad rollout or config: confirm latency starts with a rollout/config change and reverses on rollback; rule out by stable version and no relevant config diff.
Load surge or legitimate traffic reduction: confirm RPS/traffic change explains latency; rule out by stable traffic or latency without traffic change.
DNS failure: confirm DNS resolution errors/latency coincident with the symptom; rule out by normal DNS resolution.
Client/ingress issues: confirm latency/errors originate at the client/ingress side; rule out by normal client/ingress metrics and pod-local evidence.
Endpoint churn, probe failures, restarts, or readiness failures: confirm endpoint churn/probe failure/restarts/readiness loss; rule out by Running/Ready pods, zero restarts, populated endpoints, and passing probes.
Check order: pod readiness/restarts/endpoints/probes/errors, then CPU/memory/GC/node pressure, then per-pod RTT/latency vs peers and unaffected nodes, then packet rates/NIC drops/co-located comparison, then dependency/DB/cache traces, then source/config/rollout diff, then DNS/client/ingress/traffic.
