Single-Service CPU-Bound Latency Spike: Distinguishing Application Busy-Loop from Other Causes
Suspect an application busy-loop when one healthy, non-restarting workload shows a sharp CPU rise with CFS throttling and correlated latency increase while peer services, downstream dependencies, and traffic patterns remain normal.
Key distinguishing evidence: anomaly is isolated to the suspect service, no errors/restarts, no dependency saturation or latency alerts, and source inspection shows an unyielding loop in the request path.
Before concluding, rule out downstream slowness, node-level CPU contention, traffic surge/autoscaling lag, CPU limit misconfiguration, GC/memory pressure, and sidecar or other code paths consuming CPU.
Confirm the loop executes per request and that removing or yielding it restores latency without infrastructure changes.
