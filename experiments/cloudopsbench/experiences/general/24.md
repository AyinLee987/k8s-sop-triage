Missing Pod Objects Point to Namespace Admission Rejection, Not Runtime Failure
When a workload has zero ready replicas but its ReplicaSet shows 0 current / 1 desired with no pods in any state (0 Running/Waiting/Failed/Succeeded), suspect admission rejection before scheduling, image, or container failures.
Confirm by reading the namespace ResourceQuota and comparing used vs. hard for the resource matching the workload's requests (e.g., sum of CPU requests equal to the quota ceiling).
Rule out causes that leave a pod object behind: Pending pods (node capacity, taints, affinity), ImagePullBackOff, CrashLoopBackOff, failing readiness/liveness probes, and container-level limit throttling — none of these produce an empty ReplicaSet.
Also rule out quota exhaustion on other resource types (memory, object count, storage) and check whether quota scope covers only this namespace, so the fix targets the right constraint.
