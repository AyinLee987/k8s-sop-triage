Frontend 503s on /product and /cart — swapped cart RPC arguments
Symptom: boutique frontend returned 503 on GET /product/{id}, /cart, POST /cart while all pods were Running and services healthy.
Cause: frontend handlers.go/rpc.go called cartservice with userId and productId arguments reversed; cartservice logged 766 errors (~27%) "AddItemAsync called with userId=<productId>, productId=<uuid>".
First checks: GetAlerts for frontend 503s, GetErrorLogs cartservice for argument-shaped errors, GetSourceCode frontend handlers.go/rpc.go around cart RPC calls.
Confirm fix by cartservice error ratio dropping and frontend /cart returning 200.
