## 4. 限流指标

故障期间直接读 kubelet 的 cAdvisor 计数（管理员账号，只读），约 40 秒读一次：

| 题 | 容器 | 被限流的周期 / 有任务的周期（故障期间累计） |
| --- | --- | --- |
| CT16 | frontend（25m） | 477 / 1116，约 43% |
| CT16 | currencyservice（25m） | 387 / 1117，约 35% |
| CV02 | cartservice（30m） | 462 / 539，约 86% |

Agent 用的指标工具（`-Action metrics`，只能读 nodes/metrics 的账号）在健康集群上能出表。它不能和另一个运行同时跑（脚本有"同一时间只跑一个"的保护），
所以故障期间的数是用管理员账号读同一个数据源得到的。

一个会误导人的现象：**健康的 cartservice 刚启动时也会被限流**（启动以来 19%，窗口内 10%），因为 .NET 启动吃 CPU。
Agent 如果只看"启动以来"的占比，会在别的题里把它误报成原因。这是真实环境里也有的坑，不改，判分时按"多报"记。
